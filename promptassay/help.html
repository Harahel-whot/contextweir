What it does

PromptAssay opens the logs that ContextWeir records and takes each request apart, so you can see exactly what SillyTavern sent to your model: the system prompt, your card, each lorebook entry, the summary, the chat history and anything injected, each with its size. It works with chat completion and, since 0.4, text completion. It also reads the older Wellspring test logger's folders.

It only reads. It never changes your logs, cards or lorebooks.

Starting and stopping

  • Windows: the PromptAssay shortcut (made by Create Shortcuts (Windows).bat in the tools folder), or Start PromptAssay.bat in the PromptAssay folder.
  • Mac: launch/mac/Start PromptAssay.command (first time: right-click, Open). Linux: launch/linux/start-promptassay.sh.

Its window opens on the newest session. Starting it again while it runs only reopens the window (the launcher says so); to restart it, close its console window and start it again. To stop it, close the small minimised "PromptAssay" console window (Windows) or the terminal (Mac, Linux).

ContextWeir does not need to be running to read old sessions. While it records, new turns appear by themselves (untick live to hold the view still).

The demo session (made up)

At the bottom of the session list is demo (made up): The Lantern Coast: twelve requests from a small invented story, so you can try PromptAssay before setting anything up. Everything in it is invented (the coast, its people, the player "Wren", every prompt and reply); no real chat was used. It is labelled against its own card and lorebook in the demo folder, never against yours.

A second demo, 2 Jan, holds the same twelve requests as SillyTavern sends them in text completion (one prompt string, ChatML instruct template), so you can see how PromptAssay takes such a prompt apart. It is made up too.

Things to look at: the lorebook entries that enter at #1 and #4 (click one to see its exact text), the swipe at #3, the flagged reply at #4, SillyTavern's Summarize request at #6 and the summary sitting in the prompt from #7, the model change at #8, the empty reply at #9 and its regenerate at #10, Tamsin entering and the keeper leaving at #11. The demo\rules folder has the rule set that flagged them: import it on ContextWeir's Rules tab to try one. To hide the demo, set "showDemo": false in settings.json.

Reading a request

Choosing what to look at

  • The drop-down at the top picks a session (one ContextWeir run). Old logger runs say "(old logger)".
  • The timeline under it has one mark per request, coloured by its worst warning. Click a mark to open that request.
  • The list on the left shows each request with its time, size, the start of your message and any warnings. ↑ ↓ move through it.
  • flagged only and the rule filter narrow the list to the turns you care about.

The request

At the top: total size (and an estimate in tokens), how many messages, how long the reply took. Then the warnings for this turn.

The coloured bar shows where the prompt's size goes:

before the chat (system prompt, card, lorebook)   injected into the chat   chat history   after the chat (post-history instructions, notes)   reply prefill

+ entered and − left list the lorebook entries and card pieces that came into, or dropped out of, the prompt since the previous request. This is often the quickest way to see why the model suddenly forgot or remembered something.

The prompt, in order

Each message is a row you can open. Its label says where it sits:

LabelMeaning
System prompt / Before the chateverything placed above the conversation
Injected at depth Nplaced inside the conversation, N messages from the end (lorebook entries, author's notes, script notes)
After the chatpost-history instructions and notes sent last
Script requesta private request a game script sent instead of a story turn
Player / Narratorthe chat history (folded into one line; "show" opens it)
Reply start (prefill)text the model was asked to continue from

The tags on a row say what it holds: lorebook entries (blue), card fields (purple), SillyTavern blocks such as the summary (olive), and new if it changed since the previous request. Labels come from matching against your own lorebook and card files; anything that could not be matched is shown with its raw text, unlabelled.

Text completion

In chat completion SillyTavern sends a list of messages, and PromptAssay labels each one. In text completion it sends one long string: the story string, lorebook entries and the chat, with the instruct template's markers (for example <|im_start|>user) between the turns. PromptAssay takes that string apart again:

  • First it finds the lorebook entries and card fields it knows, so a marker that happens to sit inside one of them never splits the prompt.
  • Then it cuts at the instruct template's markers. It recognises the template from SillyTavern's own instruct presets (the instruct folder beside your lorebook folder, or instructDir in settings.json) or from its built-in list: ChatML, Llama 3, Gemma, Mistral, Alpaca, Vicuna, Phi and Command-R.
  • With no template but speaker names (SillyTavern sends Name: stop strings), it cuts at the names.
  • With neither, the prompt stays one block, as before.

A line above the prompt says how it was split. Labels that rest on the template say (by template): a guess, if a good one. The markers themselves are shown dimmed. Show as one block (key B) shows the prompt exactly as it was sent. Joined together, the sections are always the prompt, character for character. Text injected without its own marker (an author's note, an entry "at depth") stays inside the turn next to it; its tag still names it.

Seeing exactly what something put into the prompt

Click any tag (or any name under + entered). A popup shows that piece exactly as it was sent: macros such as {{user}} already filled in, its size and where it sits in the message. Copy text copies it; Show in the prompt opens the message and marks the piece inside it.

The popup shows lorebook entries exactly as written, including any secret lines. Do not share screenshots of it if your card has secrets.

Which versions and which model

The line under the header says what the session was recorded with:

  • Frontend: the SillyTavern version, noted by ContextWeir 0.5 or newer when the session started (if ContextWeir's SillyTavern folder is set).
  • Model server: its name and version, and the model it said was loaded (KoboldCpp reports both).
  • Model asked for: the model name each request carried. If it changed during the session, the line says where, the turn list marks the request with model changed, and the timeline marks it with a pink line on top. A request's own view says model … (changed from …).

Logs made before ContextWeir 0.5 (and the old Wellspring logger's runs) say not recorded. If your lorebook folder is set, the SillyTavern installed now is shown beside it, marked "installed now": that is today's version, not necessarily the one that made the log.

Warnings

Warnings come from ContextWeir's flag rules (you set them up in ContextWeir's window). PromptAssay shows where they fired: note, warning, serious. The matching text is highlighted inside the reply or prompt.

Settings (settings.json)

Edit with any text editor while PromptAssay is closed.

SettingWhat it does
logDirsfolders to read sessions from: ContextWeir's logs folder, and old logger folders if you have them
worldsDirSillyTavern's lorebook folder, for labelling (e.g. SillyTavern/data/default-user/worlds)
charactersDirSillyTavern's character folder, for labelling card fields (PNG cards, and cards saved as JSON)
instructDiroptional: SillyTavern's instruct preset folder, for taking text-completion prompts apart. Left empty, the instruct folder beside worldsDir is used if there is one; otherwise the built-in templates
showDemotrue (the default) lists the made-up demo session at the bottom; false hides it

Folders can be written relative to the PromptAssay folder or in full. Without worldsDir and charactersDir, sections are labelled by position only.

Privacy and safety

  • PromptAssay runs only on this computer (127.0.0.1) and only reads. It needs no internet and sends nothing anywhere.
  • Web pages in your browser cannot read your logs through it.
  • Logs hold full prompts in plain text. Keep them private.

When something goes wrong

"no sessions found" (PA-NO-SESSIONS)

Check logDirs in settings.json points at ContextWeir's logs folder, and that ContextWeir has recorded at least one turn.

Nothing is labelled

Set worldsDir and charactersDir. If you changed a lorebook entry after the turn was recorded, the old text no longer matches and shows unlabelled.

No window opens

The window gets a free port each time PromptAssay starts. Look in its console for the line window: http://127.0.0.1:… and open that address in your browser.

A very long session is slow to open

The prototype reads the whole session file when you open it; large sessions take a few seconds.

Error codes

Every known problem has a short code that never changes, shown beside the plain message: in the console, in the window. If you ask someone for help, quote the code.

CodeWhat it meansWhat to do
PA-SETTINGS-BAD-JSONsettings.json is not valid JSON. PromptAssay could not read its settings file (often a missing comma or quote after editing it by hand), so it stopped.Fix the file, or delete it and start PromptAssay again to get the defaults.
PA-SETTINGS-LOGDIRSlogDirs is not a list of folders. The "logDirs" setting must be a list of folder names in square brackets, e.g. ["../contextweir/logs"].Fix "logDirs" in settings.json, then start PromptAssay again.
PA-WINDOW-FAILEDThe window could not open. PromptAssay could not open a port for its window, so it stopped.Start it again. If it keeps happening, restart the computer; a security program may be blocking local ports.
PA-LOG-FOLDERA log folder could not be read. One of the folders in "logDirs" does not exist or cannot be read, so its sessions are not listed.Check the folder in settings.json. By default it is ContextWeir's logs folder next to PromptAssay's.
PA-NO-SESSIONSNo sessions found. The log folders hold no sessions yet (a session appears once ContextWeir has recorded at least one turn).Play a turn through ContextWeir (Start pressed, frontend pointed at it), or open the demo session that ships with the tools.
PA-LABELS-OFFLabelling is off. No lorebook or character folder is set, so sections are labelled by position only (no entry names).Set "worldsDir" and "charactersDir" in settings.json to SillyTavern's data\default-user\worlds and characters folders.
PA-LABELS-FOLDERA lorebook or character folder could not be read. The folder set in "worldsDir" or "charactersDir" does not exist or cannot be read, so nothing from it is labelled.Check the folder in settings.json (SillyTavern keeps them in data\default-user\).
PA-LABEL-FILEA lorebook or card could not be read. One file in the lorebook or character folder is not a readable lorebook or card, so it was skipped. The others are used.Usually harmless (a half-saved or non-SillyTavern file). The detail names the file.
PA-TEMPLATES-FOLDERThe instruct preset folder could not be read. PromptAssay looks in SillyTavern's instruct folder to take text-completion prompts apart. The folder in "instructDir" (or the one beside your lorebook folder) could not be read.Check "instructDir" in settings.json, or leave it empty. Without it, text-completion prompts are taken apart with the built-in templates (ChatML, Llama 3, Gemma, Mistral, Alpaca and a few more).
PA-TEMPLATE-BADAn instruct preset file was skipped. A file in the instruct folder could not be read as a SillyTavern instruct preset (damaged, too large, or not a preset).Usually harmless; the other presets and the built-in templates are still used. The detail names the file.
PA-SESSION-GONEThat session is no longer there. The page asked for a session that is no longer in the log folders (ContextWeir may have deleted it as an old session).Pick another session from the list, or reload the page.
PA-RECORD-UNREADABLEA request could not be read. A record in the session could not be read back (the log file changed, or the record is damaged).Reload the page. If it repeats for the same request, that record is damaged; the rest of the session still works.
PA-REFUSED-HOSTA request with a strange address was refused. Something asked PromptAssay for a page with a Host header that was not this computer: how web pages try DNS-rebinding tricks.Nothing to do if you did not expect it. Open PromptAssay with its Start file.
PA-REFUSED-ORIGINA request from another page was refused. A page that is not PromptAssay's own window tried to read your logs. Only the window itself may.Nothing to do if you did not expect it.
PA-READ-ONLYA request to change something was refused. PromptAssay only reads. Something tried to send it data (anything but a plain read).Nothing to do if you did not expect it.
PA-RUNNING-FILErunning.json could not be written. The Start file finds a running PromptAssay through running.json. Writing it failed, so the Start file may open the wrong window.Check the PromptAssay folder is not read-only.
UNKNOWNSomething unexpected went wrong. A problem with no code of its own.Save a diagnostic report and send it with a description of what you were doing.

Diagnostic report

To ask someone for help, use Save diagnostic report (the Report button in the header). It makes one small text file with: PromptAssay's version and build date, your Node.js version and operating system, the browser showing the window, the folders it reads and whether they can be read, how many sessions and lorebook or card pieces it found, the recent problems with their codes, and the last few dozen console lines.

  • It never holds a prompt, a reply or lorebook text.
  • Folder paths are shortened: your home folder is shown as <home>, because on Windows it usually holds your name. Tick Show full folder paths if the helper needs them.
  • The window shows the whole report before you save it. Save to a file saves exactly that text; Copy puts it on the clipboard.
  • Nothing is sent anywhere, ever: there is no automatic crash reporting. You decide whether to attach the file.
