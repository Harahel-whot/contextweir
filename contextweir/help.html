What it does

ContextWeir sits between your chat program (for example SillyTavern) and your model server (for example KoboldCpp). Everything passes through unchanged: your model sees exactly what it would have seen without ContextWeir. On the way through, ContextWeir saves each request and reply exactly as sent, and checks them against your flag rules (for example "warn if the reply starts with OOC").

To look at what it saved, use PromptAssay, its companion: it takes each request apart so you can see every piece of the prompt.

ContextWeir only works with a model server on this computer. Cloud models (OpenRouter, Claude, OpenAI and the like) are not supported.

Which APIs it records

Every request passes through, but only generation requests are saved: those sent to these addresses.

API in your frontendAddressTested
Chat Completion (SillyTavern's "Custom (OpenAI-compatible)", KoboldCpp)/v1/chat/completionsyes
Text Completion (KoboldCpp, and other OpenAI-style servers)/v1/completionsyes (made-up test data until a real capture)
KoboldCpp's own API ("KoboldAI Classic")/api/v1/generate, /api/extra/generate/streamyes (test data)
llama.cpp server's own API/completionuntested: no such server here
Ollama/api/generateuntested: no such server here

If you use one of the untested ones, please tell us whether it works: a diagnostic report is the easiest way. If your frontend generates through an address not in this list, replies still come back but nothing is saved; ContextWeir notices and says so once per session (code CW-ENDPOINT-UNKNOWN).

Starting and stopping

  • Windows: double-click the ContextWeir shortcut (made by Create Shortcuts (Windows).bat in the tools folder), or Start ContextWeir.bat in the ContextWeir folder.
  • Mac: launch/mac/Start ContextWeir.command. The first time, right-click it and choose Open.
  • Linux: launch/linux/start-contextweir.sh.

Two things open: a console window (ContextWeir itself; each turn gets a line there) and the control panel. The panel opens on its start screen: nothing is recorded, and your frontend cannot connect, until you press Start. Tick Skip this screen next time to start recording as soon as ContextWeir opens (the panel still opens, and the start screen comes back by itself if the receiving port is taken).

Starting it again while it runs only reopens the panel, and the launcher says so. To restart it, use Restart in the panel.

To stop it, press Quit in the panel: ContextWeir stops, and the console and the panel window close with it. Closing the console window also stops it. Closing only the panel window leaves ContextWeir recording; start it again with its Start file to bring the panel back.

Setting up (once)

  1. Install Node.js (version 18 or newer) if you have not already.
  2. Start your model server as usual (KoboldCpp listens on port 5001 by default).
  3. Start ContextWeir. On the Connection tab, check the receiving port (Check says whether it is free) and the model server port (Test says whether your model server answers, and which version and model it has loaded). Save if you changed anything.
  4. Press Start.
  5. In SillyTavern, open API Connections, choose Chat Completion, Custom (OpenAI-compatible), and set the address to the one the Connection tab shows, for example http://127.0.0.1:5012/v1. Connect.
  6. Play a turn. A line appears in the console, the panel counts it, and the turn shows up in PromptAssay.

To stop recording for good, point SillyTavern back at your model server's address (for KoboldCpp, http://127.0.0.1:5001/v1).

Optional, on the Logs tab: set the SillyTavern folder (the one that holds Start.bat). ContextWeir then notes SillyTavern's version in each session, so PromptAssay can tell you which version a log was made with. It reads only that folder's package.json.

The control panel

The buttons

ButtonWhat it does
StartOpens the receiving port and starts a new session. If another program has the port, nothing starts and the panel says so; the port never moves on its own, because your frontend is set to it.
Pause / ResumeWhile paused, turns still pass straight through to the model and the game keeps working, but nothing is saved. The panel counts how many passed through.
StopCloses the receiving port and ends the session. Your frontend gets errors until you press Start again. The panel stays open.
RestartApplies every saved setting (ports, model address, folders) and starts a new session.
QuitStops recording and closes ContextWeir, its console and the panel window. (Closing only the panel window keeps ContextWeir recording.)

The coloured label beside the version says the state: Ready (not recording), Recording, Paused, or Port in use.

The tabs

  • Status: the start screen while nothing is recording. While recording: the address your frontend connects to, where it forwards, where logs go, and the frontend and model server versions; then this session's numbers (requests, swipes and regenerates, flagged turns and how many per 100, average prompt size and reply time, how often each rule fired). The same numbers are saved in each session's summary.json, so you can compare a test before and after a change. A rule that took too long is listed in red as switched off this session (see slow rules).
  • Connection: the receiving port and the model server, with Check and Test.
  • Logs: the log folder, how many sessions and turns to keep, the optional SillyTavern folder, and how big the log folder is now.
  • Rules: your flag rules (below).
  • Advanced: size limits and time limits.

Flag rules

Rules are grouped in sets (for example "General", "Wellspring", "My horror card"). Changes save straight away and apply from the next turn.

  • Tick or untick a rule, or a whole set, to switch it on or off without deleting it.
  • + New set, Rename, Delete set; + Add rule, Edit, Delete.
  • Export a set (or Export all) to share it as a small file. Import… shows what a file holds, and anything that will be refused, before you choose to add it beside your sets or replace them.
  • Every save keeps the previous rules.json as rules.json.bak.

Writing a rule

A rule reads like a sentence: [what to check] [test] [value].

What to checkMeaning
the replywhat the model wrote back
the whole prompteverything sent to the model
the player's last messagethe newest message from you
the last message sentthe very last part of the prompt (often a system note or script request)

Text completion sends the whole prompt as one long string, so there "the last message sent" is the last 2,000 characters of the prompt and "the player's last message" is empty. Use contains rather than starts with on the last message, and write rules against the reply and the whole prompt, which work the same in both modes. The rule sets in contextweir\rule_sets\ (General, and Wellspring with a "contains" line beside each "starts with" one) can be imported on the Rules tab.

TestFires when
starts withthe text starts with the value (ignoring case and leading spaces)
containsthe value appears anywhere (ignoring case)
does not containthe value is missing
matches pattern (advanced)a regular expression matches; tick "ignore case" if wanted
does not match pattern (advanced)a regular expression does not match

Severity (note, warning, serious) sets the colour in PromptAssay. Exceptions ("…unless any of these") skip the rule in special cases, for example: the reply does not contain "[Time:" … unless the last message sent starts with "[Private system request". The note explains why the rule exists; it travels with exported files.

Slow rules

Some patterns can take a very long time on unlucky text. ContextWeir refuses the usual problem shapes when you save, and also runs all rules with a time limit (ruleTimeoutMs, 1 second per turn by default). If a rule goes over, it is stopped, named in that turn's flags and in the console, and switched off until ContextWeir restarts or you save the rules again. Your game is never slowed: the reply has already gone back before rules run.

Settings

Change settings on the panel's tabs and press Save on that tab. Each setting says when it takes effect: applies now (the next turn uses it) or needs Restart (press Restart, or Stop and Start). A save with any problem is refused as a whole, with the reason, and nothing is written. Every save keeps the previous file as settings.json.bak.

The same settings live in settings.json, which you can also edit with a text editor while ContextWeir is closed; wrong values stop it at start with a message saying which.

Moving or sharing your setup (settings and rules in one file)

On the Advanced tab, Export settings and rules saves one file (contextweir-setup_….json) with your settings and every rule set: a backup, a copy for another computer, or a setup to share with someone. Folder settings (the log folder and the SillyTavern folder) belong to one computer and usually hold your name, so they go in only if you tick include folder settings.

Import a setup file… never changes anything straight away. It shows a preview: each setting that would change (now, and from the file, and whether it applies now or needs Restart), the rule sets in the file, and anything that cannot be used. Then you choose: the settings or not, the folder settings or not, and for the rule sets add beside yours, replace all yours, or leave yours alone. Everything goes through the same checks as the panel, so a file cannot point ContextWeir at a model server off this computer. The previous settings.json and rules.json are kept as .bak.

A single rule set still exports and imports on its own from the Rules tab (that is the file to ship with a character card). PromptAssay has nothing to export: its only settings are the folders it reads.

Privacy and safety

Logs hold full prompts and replies in plain text, including secrets in your cards and anything you typed. Keep the logs folder private and never share it.
  • ContextWeir only listens on this computer (127.0.0.1) and only forwards to a model server on this computer.
  • Web pages in your browser cannot read your logs, change your settings or rules, or press the panel's buttons through it; only the panel's own window can. The panel cannot point ContextWeir at another computer.
  • It never saves request headers (where API keys travel), installs nothing, downloads nothing and needs no internet.
  • Never expose SillyTavern or these tools to the internet. If you use remote access (e.g. Tailscale), keep SillyTavern's whitelist or login on.

When something goes wrong

"ContextWeir needs Node.js"

Install Node.js 18 or newer from nodejs.org, then start again.

"The receiving port … is already in use" (label: Port in use; CW-PORT-TAKEN)

Another program (or a second ContextWeir, or an older logger) uses that port. Close it and press Start, or choose another port on the Connection tab, save, press Restart, and use the new address in SillyTavern.

SillyTavern says it cannot connect

Is the label Recording? On the start screen, or after Stop, the receiving port is closed: press Start. Check the address in SillyTavern matches the Connection tab. Check your model server with Test: the console also says "could not reach the model server" if it is not running.

I changed a setting and nothing happened

Settings marked needs Restart wait for Restart; a yellow bar says so, with a Restart now button.

No window opens

The launcher opens your default browser; Chrome, Edge, Brave and Vivaldi give an app-style window, others a normal tab. If nothing opens, look in the console for the line window: http://127.0.0.1:… and open that address yourself (the port changes each start).

I double-clicked Start and only the window came back

ContextWeir was already running, so the launcher only reopened its panel (it says so). Use Restart in the panel to restart it.

Nothing appears in the console when I play

SillyTavern is still pointed at the model server directly, or recording is Paused.

A rule fires on every turn

Open it in the editor and add an exception, or untick it. In PromptAssay, the rule filter shows exactly where it fired.

The logs folder is getting big

The Logs tab shows its size. Lower Sessions to keep or Most turns per session.

Error codes

Every known problem has a short code that never changes, shown beside the plain message: in the console, in the window, in the red bar (with a What does this mean? button that opens this table) and in the error your frontend receives. If you ask someone for help, quote the code.

CodeWhat it meansWhat to do
CW-PORT-TAKENThe receiving port is already in use. Start could not open the receiving port because another program has it: often another copy of ContextWeir, the old logger, or something else on that port.Close whatever has the port (look for another ContextWeir console), then press Start again. Or choose another port on the Connection tab and change the address in your frontend to match. ContextWeir never moves the port on its own.
CW-PORT-FAILEDThe receiving port could not be opened. The operating system refused to open the receiving port for a reason other than it being in use.Try another port from 1024 to 65535 on the Connection tab. A security program may be blocking it.
CW-WINDOW-FAILEDThe control panel could not open. ContextWeir could not open a port for its own window, so it stopped.Start it again. If it keeps happening, restart the computer; a security program may be blocking local ports.
CW-SESSION-FOLDERNo session folder could be made. Recording could not start because ContextWeir could not create a session folder in the log folder.Check the log folder on the Logs tab exists and that you can write to it (not a read-only or cloud-only folder), then press Start.
CW-LOG-WRITEA turn could not be saved. A request and its reply passed through, but writing them to records.jsonl failed (a full disk, or the file locked by another program).Free some disk space or close programs that might hold the log file open. Turns keep passing through to the model meanwhile.
CW-MODEL-UNREACHABLEThe model server did not answer. ContextWeir could not reach the model server at the address on the Connection tab, so your frontend got an error.Start KoboldCpp (or your model server) and check its port matches "Model server port" (KoboldCpp's default is 5001). The Test button on the Connection tab checks it.
CW-MODEL-TIMEOUTThe model went silent. The model server sent nothing for longer than the model timeout, so ContextWeir gave up on that request.A very slow model or a long reply may need a longer "Model timeout" (Advanced tab). Check KoboldCpp has not frozen or run out of memory.
CW-MODEL-NOT-ANSWERINGThe model server did not answer when the session started. At the start of a session ContextWeir asks the model server for its version. It got no answer, so no version was noted. Recording still works.Usually harmless if KoboldCpp was started after ContextWeir. If turns fail too, see CW-MODEL-UNREACHABLE.
CW-REQUEST-TOO-LARGEA request was too large. The frontend sent a request larger than "Largest request (MB)", so it was refused.Raise "Largest request (MB)" on the Advanced tab if your prompts really are that large.
CW-ENDPOINT-UNKNOWNTurns are passing through but not being recorded. Your frontend is generating through an address ContextWeir does not record (the address is shown beside the code). Replies still come back, but nothing is saved for those turns.Check your frontend's API type. ContextWeir records Chat Completion, Text Completion, KoboldCpp's own API (KoboldAI Classic), llama.cpp's /completion and Ollama's /api/generate (the last two untested). If you use another server or API, send a diagnostic report so its address can be added.
CW-REFUSED-HOSTA request with a strange address was refused. Something sent a request whose Host header was not this computer. This is how web pages try DNS-rebinding tricks; ContextWeir refuses them.Nothing to do if you did not expect it. Point your frontend at http://127.0.0.1:<port>/v1, not a computer name.
CW-REFUSED-ORIGINA request from a web page was refused. A page open in your browser (or another local web app) tried to send a request. Only programs, and the panel's own window for settings, are allowed.Nothing to do if you did not expect it. If your frontend runs in a browser and was refused, tell us: SillyTavern sends from its server, not the page.
CW-SETTINGS-BAD-JSONsettings.json is not valid JSON. The settings file could not be read (often a missing comma or quote after editing it by hand).Fix the file, or delete it and start ContextWeir again to get the defaults (settings.json.bak holds the previous version). "node contextweir.js --check" points at the problem.
CW-SETTINGS-PROBLEMSsettings.json has problems. One or more settings are out of range, unknown, or point somewhere ContextWeir will not write. The list names each one.Fix the named settings in the panel (or in the file while ContextWeir is closed). "node contextweir.js --check" lists them.
CW-SETTINGS-WRITEsettings.json could not be saved. The panel checked your settings but could not write the file.Check the ContextWeir folder is not read-only and that no other program has settings.json open.
CW-SILLYTAVERN-FOLDERThe SillyTavern folder was left out. The optional SillyTavern folder (used only to note its version) has no package.json, so it was left out for this run. Recording is not affected.On the Logs tab, choose the folder that holds SillyTavern's Start.bat, or leave the setting empty.
CW-RULES-MISSINGrules.json was not found. There is no rules.json, so no flag rules are checked. Recording still works.Import a rule file on the Rules tab, or add a set there; saving creates rules.json.
CW-RULES-BAD-JSONrules.json is not valid JSON. The rule file could not be read, so no flag rules are checked. Recording still works.rules.json.bak holds the previous version. "node contextweir.js --check-rules rules.json" points at the problem.
CW-RULES-PROBLEMSSome rules could not be used. Some rules in the file were refused (an unknown test, an empty value, a pattern that could run very slowly...). The others work.The Rules tab lists each refused rule and why. Edit or delete it there.
CW-RULES-WRITErules.json could not be saved. The rules were checked but the file could not be written.Check the ContextWeir folder is not read-only and that no other program has rules.json open.
CW-RULE-TIMEOUTA rule took too long and was switched off. One rule took longer than the rule time limit on a turn, so it was switched off for this session. Play was never delayed.Edit that rule's pattern (simpler, or plain text instead of a pattern) and save the rules to try it again.
CW-RULE-WORKERThe rule checker stopped. The thread that checks the rules failed and was started again. That turn may be missing its flags.Usually harmless. If it repeats, save a diagnostic report and send it with a description of your rules.
CW-RUNNING-FILErunning.json could not be written. The Start file finds a running ContextWeir through running.json. Writing it failed, so the Start file may open the wrong window.Check the ContextWeir folder is not read-only.
UNKNOWNSomething unexpected went wrong. A problem with no code of its own.Save a diagnostic report and send it with a description of what you were doing.

Checking files, and help for AI assistants

If you edit settings.json or a rule file by hand (or an AI assistant does it for you), check it before starting ContextWeir. In a terminal, in the ContextWeir folder:

node contextweir.js --checkchecks settings.json and rules.json
node contextweir.js --check-settings <file>checks one settings file
node contextweir.js --check-rules <file>checks one rule file, e.g. before you share it with a card
node contextweir.js --schema settings|rules|setupprints a JSON Schema (the same ones are in the schemas folder)

These run exactly the checks ContextWeir uses at start-up and in this panel, list every problem, and never start recording, open a port or change a file. Exit code 0 means no problems, 1 problems found, 2 a file could not be read, 3 a wrong option. Edit the files only while ContextWeir is closed: while it runs, the panel keeps its own copy and its next save replaces the file.

AI_HELPERS.md in the tools folder is a guide written for AI assistants (Claude Code and the like): the folder layout, every setting with its limits, the rule format with examples, the log format, the safe way to make changes, and what an assistant must never do (point ContextWeir off this computer, delete or share logs).

Diagnostic report

To ask someone for help, use Save diagnostic report (the panel's Status tab, under "Something not working?"). It makes one small text file with: ContextWeir's version and build date, your Node.js version and operating system, the browser showing the window, the settings in use, the current state, the SillyTavern and model server versions seen, the session's numbers, how many rules you have and any that were refused or switched off, the log folder's size, the recent problems with their codes, and the last few dozen console lines.

  • It never holds a prompt, a reply or lorebook text (rule patterns are left out of error messages too).
  • Folder paths are shortened: your home folder is shown as <home>, because on Windows it usually holds your name. Tick Show full folder paths if the helper needs them.
  • The window shows the whole report before you save it. Save to a file saves exactly that text; Copy puts it on the clipboard.
  • Nothing is sent anywhere, ever: there is no automatic crash reporting. You decide whether to attach the file.
